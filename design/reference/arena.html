Ticket onsale

A popular concert opens ticket sales at noon. Thousands of customers arrive at once to browse seats and check out.

Goal

Design a system that can support 100,000 concurrent users while protecting seat inventory and keeping checkout available.

Constraints

Infrastructure budget
$2,500 / month
Target latency
P95 under 250 ms
Traffic pattern
Sudden onsale spike

What matters

  • A seat should never be sold twice.
  • Checkout should remain available if an app server fails.
  • Both sides will face the same workload and failure tests.
